# Q1: Ideation - pain points in NeuronForge's PM workflow

**Context.** NeuronForge PMs/TPMs turn meetings into PRDs, epics and stories by hand. The problem statement names five symptoms: time lost gathering scope, manual and iterative translation into PRDs, inconsistent PRD formats, requirements lost in unread notes, and slower time-to-market. The sample data shows the cause clearly. Real inputs are detailed (Transcript 1), vague (Transcript 2), contradictory (Transcript 3), carry implicit acceptance criteria (Transcript 4) or are fragments (Transcript 5).

| # | Pain point | Manual step today | Agent solution in PRD Genie | Inputs → Outputs | Risks and mitigation |
|---|---|---|---|---|---|
| 1 | Requirements buried in transcripts | PM re-reads transcripts and notes, highlights asks, retypes them | **A1 Requirement Extractor** pulls functional, non-functional, constraint, stakeholder, deadline and dependency items, each with an exact quote and line number | Transcript / brief / notes → JSON of stated requirements, ambiguous items, conflicts | **Invented requirements.** Mitigated by mandatory quotes plus a code-level Grounding Verifier that drops any item not found in the source |
| 2 | Vague asks treated as requirements | PM guesses what "make it smarter like Competitor X" means | A0 gate + A1 classify vague statements as **ambiguous**, with the question that would resolve them | Vague brief → "insufficient" status + clarifying questions | **Over-filling gaps.** Mitigated by the vague-input rule in every prompt and test cases T2, T5 and T9 |
| 3 | Contradictions resolved silently | Whoever writes the PRD picks a side (e.g. 5-second refresh vs minimise API calls) | A1 records **conflicts** with both sides and owners; A4 turns them into blocking questions | Transcript → conflict list → Open Questions in the PRD | **Bias toward one stakeholder.** Prompt rule: never pick a winner; T3 and T6 check this |
| 4 | Inconsistent PRD formats | Each PM uses their own layout; engineering cannot compare or estimate | **A2 PRD Generator** fills the standard 10-section `prd_template.md` every time, citing a requirement id on each line | Approved extraction + template → Markdown/Word PRD | **Template filled with plausible filler.** Rule: unknown = TBD + Open Question; T11 checks that only T1 content appears |
| 5 | Slow, uneven story writing | PM hand-writes epics and stories; personas get merged into a generic "user" | **A3 Story Breakdown** writes epics, features and "As a [persona]" stories with verbatim acceptance criteria and MoSCoW priority | PRD → epics, stories, priorities | **Extra acceptance criteria or merged personas.** Rules plus T4, T8 and T12 |
| 6 | Missing information found late | Gaps surface in sprint planning or estimation | **A4 Gap Analyzer** checks against a PRD readiness checklist and drafts questions per stakeholder | Extraction + PRD → gap list, risks, readiness status | **Noise.** Gaps must cite evidence or say "not mentioned" |
| 7 | Estimation needs a separate meeting | Engineering sizes stories from scratch | **A5 Scope Estimator** gives S/M/L/XL with the quoted complexity signals and flags underspecified stories | Stories → size + reasons | **False precision.** Uses "UNSIZED" when the signals are missing; no hours or sprint counts |
| 8 | No trust or audit trail | Reviewers cannot see where a PRD line came from | Two **human-in-the-loop** checkpoints plus Langfuse traces of every agent call | Each run → trace, edit log, eval results | **Automation complacency.** Nothing reaches stakeholders without PM approval; the PM edit rate is tracked |
| 9 | Multilingual meetings lose detail (our addition) | Tamil/Tanglish discussions are summarised from memory in English | **A0 Intake** translates faithfully, numbers lines and keeps vague words vague | Tamil/Tanglish text or speech-to-text output → numbered English lines + original | **Translation drift.** The original lines are kept next to the translation for the PM to check |

**Expected impact.** PRD drafting moves from hours of rewriting to minutes of review. Every PRD line is traceable to a source quote. Open questions surface before sprint planning instead of during it.
